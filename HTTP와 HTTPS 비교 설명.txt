HTTP : 브라우저와 서버가 요청과 응답을 주고 받는 규칙
HTTPS : TLS로 보호되는 HTTP 통신
TLS : 통신을 보호하고 서버 인증서 확인에 사용되는 기술
암호화화 평문 : 평문은 읽을 수 있는 원래 내용, 암호화된 데이터는 통신 중 내용을 그대로 읽기 어렵게 바뀐 데이터
인증서와 개인키 : 인증서는 서버 신원과 공개키 정보를 담고, 개인키는 서버만 보유
PKCS12와 p12 : PKCS12는 인증서와 개인키를 파일에 보관하는 형식, .p12는 확장자
keytool : JDK에 포함된 인증서 키관리 프로그램
curl(컬) : 주소로 HTTP&HTTPS 요청을 보내고 응답을 확인하는 프로그램
공개키 : 공개, 인증서에 포함
개인키 : 서버만 비밀로 보관해야함(이번 실습에는 .p12 파일에 보관)
(실습 내용)
http: 8081 → curl.exe --noproxy "*" -d "note=classroom" http://127.0.0.1:8081/ # http 서버에 전송 요청(post 요청)
→ 와이어 샤크에서 전송/ 응답 내용 : received: note=classroom
---------------------------
https: 127.0.0.1: 8445 =▶ curl.exe --noproxy "*" -d "note=classroom" https://127.0.0.1:8445/
=▶  인증서 검증 오류
classroom-local.p12 인증서를 생성(keytool 이용) =▶ 신뢰성이 떨어짐
=▶ -k  옵션: 인증 검사 건너 뜀(실습용 실전X)
curl.exe -k --noproxy "*" -d "note=classroom" https://127.0.0.1:8445/
=▶ 터미널: received: note=classroom 확인
=▶ 와이어샤크에서 전송/응답 내용 : 암호화로 되어 있어 읽을 수 없음
결과 : HTTP는 요청 내용을 전송 중 읽을 수 있지만 HTTPS는 TLS로 통신 내용을 보호하며 인증서를 통해 서버 신원을 확인함
http  : 요청 성공,  와이어샤크 전송 내용에서는   읽을수 있음
https : 인증서 검증 오류로 중단, 정상요청이 안됨
https, -k : 인증서 검증을 생략하여 요청 성공, 내용이 암호화되어 그대로 읽히지 않음
